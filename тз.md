# Техническое задание: Tripavela на Flutter

**Tripavela** — мобильное приложение, которое превращает самостоятельную прогулку по городу в небольшое приключение. Пользователь задаёт условия, выбирает подходящий сценарий и постепенно открывает остановки, истории и добровольные задания.

Первая версия работает **на локальных моковых данных, без API и обязательной регистрации**. При этом пользователь должен пройти весь основной сценарий: от выбора прогулки до завершённого маршрута и сохранённых открытий в личном атласе.

Ниже — ТЗ для проектирования интерфейса и разработки. Названия мест, цены и истории в демонстрационных данных считаются вымышленными или непроверенными.

---

## 1. Границы первой версии

### 1.1. Что реализуем

- Онбординг.
- Выбор демонстрационного города.
- Подбор прогулки по условиям.
- Каталог подготовленных маршрутов.
- Предпросмотр маршрута без раскрытия мест.
- Последовательное прохождение остановок.
- Ручное подтверждение прибытия.
- Истории мест и добровольные миссии.
- Одну подготовленную развилку в маршруте.
- Пропуск и замену остановки.
- Паузу и досрочное завершение.
- Полное раскрытие маршрута по желанию.
- Сохранение прогресса между запусками.
- Итоги прогулки.
- Личный атлас.
- Фотографии и заметки.
- Избранные маршруты.
- Настройки и управление локальными данными.
- Демонстрационные состояния: закрытое место, неподходящая погода, отсутствие подходящих маршрутов.

### 1.2. Что не реализуем

- Сервер, авторизацию и синхронизацию между устройствами.
- Генерацию маршрутов AI.
- Реальные платежи.
- Реальные бронирования.
- Автоматическую проверку часов работы.
- Автоматическую замену мест на основе погоды.
- Социальную сеть, рейтинги пользователей и публичные профили.
- Фоновое отслеживание геопозиции.
- Автоматическое подтверждение прибытия.
- Полноценную картографическую навигацию внутри приложения.

**Платёжные экраны в MVP не нужны.** Все демонстрационные маршруты доступны бесплатно.

### 1.3. Платформы и ориентация

- Flutter-приложение для iOS и Android.
- Основная ориентация — портретная.
- Интерфейс корректно работает на компактных и больших смартфонах.
- На планшете контент ограничивается по ширине и центрируется.
- Основной язык — русский.
- Все строки вынесены в локализацию для последующего добавления других языков.

## 2. Основные принципы UX

### 2.1. Сюрприз касается мест, а не условий

До старта обязательно показывать:

- примерную длительность с диапазоном;
- пешую дистанцию;
- количество остановок;
- предполагаемые расходы на человека;
- обязательные расходы;
- лестницы и особенности покрытия;
- ограничения доступности;
- необходимость бронирования;
- время, до которого желательно начать;
- приблизительный район завершения.

Названия, фотографии и точные координаты скрытых мест не должны случайно появляться в предпросмотре, семантических подписях, уведомлениях или превью карты.

### 2.2. Пользователь сохраняет контроль

На активной прогулке всегда доступны:

- пауза;
- пропуск;
- замена, если она предусмотрена;
- раскрытие оставшегося маршрута;
- завершение прогулки;
- возврат к текущей остановке.

Миссии не блокируют движение.

### 2.3. Один очевидный следующий шаг

Главный экран каждого этапа содержит одну основную кнопку:

- «Подобрать прогулку»;
- «Показать маршруты»;
- «Начать прогулку»;
- «Я на месте»;
- «Продолжить»;
- «Открыть следующую остановку»;
- «Завершить прогулку».

Второстепенные действия визуально слабее основного.

### 2.4. Не заставлять смотреть в телефон

- Истории короткие и разбиты на небольшие смысловые блоки.
- Навигация открывается одним нажатием.
- Возвращение из карт восстанавливает тот же экран.
- Нет обязательного таймера, проверки фотографий и заданий на скорость.
- Следующая точка не открывается автоматически поверх текущей истории.

### 2.5. Честно обозначать демонстрационный режим

На главной и перед началом прогулки показывать компактное обозначение:

> Демоверсия · места и условия требуют проверки

Не повторять предупреждение на каждом шаге.

## 3. Информационная архитектура

### 3.1. Основная навигация

Нижняя панель из четырёх разделов:

| Раздел | Назначение |
|---|---|
| **Обзор** | Начало подбора, рекомендации, возвращение к активной прогулке |
| **Маршруты** | Каталог, фильтры и избранное |
| **Атлас** | Посещённые места, заметки, история прогулок |
| **Профиль** | Предпочтения, настройки и локальные данные |

«Профиль» в MVP — локальное пространство пользователя без аккаунта.

### 3.2. Вложенные экраны

**Обзор → Подбор → Результаты → Описание маршрута → Подготовка → Активная прогулка.**

**Активная прогулка → Прибытие → История места → Миссия → Следующая остановка / Развилка → Итоги.**

**Атлас → Открытие / Завершённая прогулка → Заметки и фотографии.**

### 3.3. Поведение нижней панели

- Видна в четырёх основных разделах.
- Скрыта во время онбординга, пошагового подбора и прохождения маршрута.
- При переходе между разделами сохраняются фильтры и положение прокрутки.
- Повторное нажатие на выбранный раздел прокручивает его основной экран вверх.
- Системная кнопка «Назад» сначала закрывает модальное окно, затем возвращает по стеку.

### 3.4. Активная прогулка вне экрана прохождения

Если прогулка начата, на основных разделах над нижней навигацией появляется компактная панель:

**«Прогулка продолжается · остановка 2 из 4» → «Вернуться».**

При паузе:

**«Прогулка на паузе» → «Продолжить».**

Допускается только одна незавершённая прогулка одновременно.

## 4. Общая структура интерфейса

### 4.1. Сетка и отступы

Все размеры указаны в логических пикселях Flutter.

| Элемент | Требование |
|---|---|
| Боковые отступы | 20 |
| Отступы между крупными секциями | 24–32 |
| Между связанными элементами | 8–12 |
| Внутренний отступ карточки | 16 |
| Высота основной кнопки | Не менее 52 |
| Минимальная зона нажатия | 48 × 48 |
| Скругление карточек | 20 |
| Скругление кнопок | 16 |
| Максимальная ширина основного контента | Около 640 |

Не задавать фиксированную высоту карточкам с текстом.

### 4.2. Типографика

- Заголовок экрана: 28–32.
- Заголовок секции: 20–22.
- Заголовок карточки: 18–20.
- Основной текст: 16.
- Вспомогательный текст: 14.
- Подписи и метаданные: не менее 12.

Основной текст должен комфортно читаться на улице. Светло-серый текст с низким контрастом не использовать.

### 4.3. Визуальное направление

Стиль — спокойный городской путеводитель с ощущением приключения.

- Тёплый светлый фон.
- Тёмный контрастный текст.
- Один основной акцентный цвет.
- Второй цвет для открытий и игровых элементов.
- Фотографии и иллюстрации поддерживают содержание.
- Минимум декоративных значков и конфетти.

Игровые элементы не должны создавать ощущение детской игры.

### 4.4. Фиксированные нижние действия

На экранах с основным действием используется нижняя панель:

- фон отделён от контента;
- учтена системная безопасная область;
- кнопка не перекрывает последние элементы списка;
- при открытой клавиатуре поле ввода и действие остаются доступны.

### 4.5. Модальные поверхности

**Bottom sheet** использовать для:

- выбора города;
- сортировки;
- меню прогулки;
- причин пропуска;
- замены места;
- фильтров.

**Диалог подтверждения** использовать для:

- сброса данных;
- завершения незаконченной прогулки;
- раскрытия всех мест;
- удаления заметки или фотографии.

**Полноэкранный экран** использовать для:

- подбора;
- просмотра истории;
- ввода длинной заметки;
- галереи фотографий.

# 6. Экраны первого запуска

## S01. Запуск

**Назначение:** восстановить локальное состояние и определить стартовый экран.

### Состав

По центру:

- логотип;
- название Tripavela.

Внизу — необязательный короткий слоган.

### Логика

После инициализации:

- первый запуск → онбординг;
- онбординг пройден, город не выбран → выбор города;
- остальные случаи → обзор;
- активная прогулка восстановлена → обзор с заметной карточкой продолжения.

Искусственную задержку для демонстрации загрузки не добавлять.

Если локальное состояние повреждено, приложение запускается с безопасными значениями. Пользовательские фотографии и заметки не удаляются автоматически.

## S02. Онбординг

Три страницы с горизонтальным переключением.

### Расположение

**Сверху справа:** «Пропустить».

**Верхняя половина:** иллюстрация.

**Ниже:**

1. заголовок;
2. короткое объяснение;
3. индикатор из трёх страниц.

**Внизу:** основная кнопка.

### Содержание

**Страница 1 — «Город приготовил кое-что интересное»**

> Выберите настроение, время и бюджет. Мы предложим прогулку с небольшими открытиями.

Кнопка: «Дальше».

**Страница 2 — «Следующее место — маленький сюрприз»**

> Остановки открываются постепенно. Длительность, расходы и важные условия видны заранее.

Кнопка: «Дальше».

**Страница 3 — «Приключение в вашем темпе»**

> Пропускайте задания, меняйте остановки и завершайте прогулку, когда захотите.

Кнопка: «Выбрать город».

### Поведение

- «Пропустить» ведёт к выбору города.
- Разрешения не запрашиваются.
- После завершения онбординг больше не появляется автоматически.
- Повторно доступен из раздела «О приложении».

## S03. Выбор города

### Расположение

**Верхняя панель:**

- заголовок «Где погуляем?»;
- кнопка закрытия, если экран открыт из основного приложения.

**Ниже:**

- пояснение «В демоверсии доступен один город»;
- поле поиска;
- список доступных городов;
- отдельный блок «Другие города появятся позже».

### Карточка доступного города

- изображение;
- название;
- страна;
- количество маршрутов;
- отметка «Демогород»;
- индикатор выбора.

**Внизу:** кнопка «Продолжить».

### Поведение

- Поиск работает локально.
- Недоступные города нельзя выбрать.
- Для пустого поиска: «Пока нет такого города. Попробуйте другое название».
- Автоопределение местоположения в MVP отсутствует.
- Смена города не удаляет атлас и историю.

# 7. Обзор и подбор

## S04. Обзор

### Расположение сверху вниз

**1. Верхняя панель**

Слева:

- подпись «Ваш город»;
- название города и стрелка раскрытия.

Справа:

- кнопка избранного с иконкой закладки.

**2. Карточка активной прогулки**

Показывается только при наличии незавершённой сессии.

Содержит:

- статус «Продолжается» или «На паузе»;
- название;
- «Посещено 2 из 4 остановок»;
- основную кнопку «Вернуться к прогулке».

Эта карточка располагается выше предложений начать новую.

**3. Главный блок**

Заголовок:

> Какое приключение устроим сегодня?

Подзаголовок:

> Подберём прогулку под ваше настроение.

Основная кнопка: «Подобрать прогулку».

Вторичная ссылка: «Посмотреть все маршруты».

**4. Быстрые сценарии**

Горизонтальные чипы:

- «На пару часов»;
- «Еда и открытия»;
- «Хочется тишины»;
- «Для двоих».

Нажатие открывает подбор с заполненными условиями. Маршрут автоматически не запускается.

**5. Секция «Для первого знакомства»**

2–3 карточки маршрутов.

**6. Секция «Выберите настроение»**

Сетка 2 × 3:

- гастрономия;
- искусство;
- спокойная прогулка;
- городские истории;
- необычные места;
- совместный досуг.

**7. Краткий блок «Как это работает»**

Три компактных пункта:

1. Выберите условия.
2. Открывайте места по пути.
3. Сохраните свою историю дня.

**8. Пометка демоверсии.**

### Карточка маршрута

- изображение без спойлеров;
- название;
- краткое атмосферное описание, максимум две строки;
- длительность;
- дистанция;
- бюджет;
- количество остановок;
- 1–2 тематических тега;
- кнопка избранного.

Не использовать рейтинги и отзывы, если за ними нет реальных данных.

## Общие правила подбора

Подбор состоит из трёх шагов.

На каждом:

- сверху — «Назад»;
- заголовок;
- индикатор «Шаг 1 из 3»;
- прокручиваемое содержимое;
- снизу — фиксированная кнопка.

Выбранные значения сохраняются при возврате назад.

Если пользователь закрывает подбор, черновик сохраняется. При следующем входе предлагается продолжить с последними условиями.

## S05. Настроение и интересы

### Состав сверху вниз

**Заголовок:** «Чего хочется сегодня?»

**Подсказка:** «Выберите одно настроение и до трёх интересов».

### Блок «Настроение»

Карточки в сетке:

- «Удивиться»;
- «Замедлиться»;
- «Попробовать новое»;
- «Почувствовать город»;
- «Провести время вместе»;
- «Довериться случаю».

Выбирается одно значение.

### Блок «Интересы»

Чипы с множественным выбором:

- еда;
- искусство;
- история;
- архитектура;
- природа;
- мастерские;
- книжные;
- городские детали.

Интересы необязательны.

При попытке выбрать четвёртый:

> Можно выбрать до трёх интересов.

Уже выбранные значения не сбрасываются.

### Блок «С кем идёте?»

Одно значение:

- один / одна;
- вдвоём;
- с друзьями;
- с детьми.

Выбор «С детьми» открывает дополнительное поле возрастной группы. В MVP использовать простые категории, без сбора точного возраста.

**Нижняя кнопка:** «Дальше».

## S06. Время и бюджет

### Заголовок

«Сколько времени на приключение?»

### Блок времени

Варианты:

- до 1 часа;
- до 2 часов;
- до 4 часов;
- до 6 часов.

Ниже подпись:

> Учитываем переходы, остановки и время на отдых.

### Блок «Когда начнёте?»

- «Сейчас»;
- «Выбрать время».

Для второго варианта — локальный выбор даты и времени в пределах доступного демонстрационного расписания.

Приложение явно сообщает:

> Доступность рассчитана по демонстрационному расписанию.

### Блок бюджета

Заголовок: «Бюджет на человека».

Варианты:

- бесплатно;
- экономно;
- умеренно;
- без строгого лимита.

У каждого, кроме последнего, отображается числовой предел в валюте выбранного города. Значения задаются данными, не зашиваются в UI.

Подпись:

> Еда, билеты и транспорт оплачиваются отдельно. Необязательные покупки можно пропустить.

### Важное поведение

- «Бесплатно» исключает маршруты с обязательными расходами.
- Бесплатная прогулка может содержать необязательное предложение купить напиток.

# 9. Прохождение прогулки

## S12. Путь к остановке

Это основной рабочий экран во время прогулки.

### Расположение сверху вниз

**1. Верхняя панель**

Слева — кнопка сворачивания к обзору.

По центру — короткое название прогулки.

Справа — меню «Ещё».

Сворачивание не ставит прогулку на паузу.

**2. Прогресс**

> Остановка 2 из 4

Ниже — сегментированный индикатор:

- посещённые;
- текущая;
- будущие;
- пропущенные.

Статусы различаются не только цветом.

**3. Карточка текущего места**

- категория;
- название;
- фотография;
- адрес;
- краткое объяснение «Почему идём сюда»;
- ориентировочное время на месте;
- сведения о расходах;
- условия входа.

**4. Карточка перехода**

- расстояние от предыдущей точки;
- расчётное время пешком;
- особенности пути;
- кнопка «Открыть в картах».

Для первой остановки — адрес и район. Не показывать фиктивное расстояние «от вас».

**5. Необязательная подсказка**

Например:

> Вход во двор находится справа от арки.

**6. Вторичные действия**

- «Место закрыто или не подходит»;
- «Пропустить остановку».

**7. Фиксированная нижняя панель**

Основная кнопка: «Я на месте».

### После «Я на месте»

- точка получает статус «Посещена»;
- создаётся запись атласа;
- открывается история места;
- повторное нажатие не создаёт дубликаты.

Первый раз можно показать короткую подсказку:

> Подтверждение ручное — геопозиция не нужна.

Повторно её не показывать.

### Открытие внешних карт

- Использовать URL-схему или универсальную ссылку.
- При наличии выбора приложений — системный выбор.
- При ошибке показать адрес и кнопку «Скопировать адрес».
- Возврат из карт не считается прибытием.
- Внешние карты могут требовать интернет; основное приложение от этого не зависит.

После раскрытия нельзя свободно переключать ветки как вкладки. Изменение возможно через обычную замену остановки.

## S17. Замена остановки

Открывается через «Место закрыто или не подходит».

### Шаг 1. Причина

Bottom sheet:

- закрыто;
- слишком многолюдно;
- изменилась погода;
- не хочется сюда;
- трудно добраться;
- другое.

Комментарий необязателен.

### Шаг 2. Альтернативы

Показывать 1–2 подготовленных варианта.

Карточка:

- тип впечатления;
- отличие от текущего;
- изменение времени;
- изменение дистанции;
- изменение расходов;
- условия доступности;
- название скрыто, если сохраняется режим сюрприза.

Кнопка: «Выбрать замену».

### Поведение

- Замена сохраняет причины и исходную точку в сессии.
- Исходное место не попадает в атлас.
- После подтверждения открывается новое место.
- Если замена нарушает исходный лимит времени или бюджета, это явно показывается.
- Ограничения доступности не нарушаются без явного изменения пользователем соответствующего требования.

### Нет альтернативы

> Для этой остановки пока нет подходящей замены.

Действия:

- «Пропустить и продолжить»;
- «Вернуться»;
- «Завершить прогулку».

## Пропуск остановки

Подтверждение в bottom sheet:

> Пропустить это место?

Необязательная причина:

- нет времени;
- неинтересно;
- закрыто;
- устал / устала;
- другое.

Кнопка: «Пропустить».

### Результат

- статус «Пропущена»;
- следующая точка становится текущей;
- место не добавляется в посещённый атлас;
- прогресс явно различает посещение и пропуск.

Не писать «Посещено 3 из 4», если две остановки были пропущены.

Правильный вариант:

> Посещено 1 · пропущено 2 · осталось 1

После завершения открыть итоги.

Если не посещено ни одного места:

- показать мягкий экран завершения;
- не создавать открытия;
- сохранить запись о незавершённом опыте в истории;
- предложить повторить маршрут позже.

# 10. Итоги и личный атлас

## S19. Итоги прогулки

### Расположение сверху вниз

**1. Заголовок**

При полном прохождении:

При досрочном завершении:

**2. Название и дата.**

**3. Основные показатели**

- выполнено миссий;

**4. Схема посещённых мест.**

**5. Лента открытий**

Фотографии или изображения мест, названия, короткие подписи.

Вопрос:

> Как вам прогулка?

- «Что можно улучшить?» — чипы;

- «Времени хватило?» — да / было мало / было с запасом;

- «Готово».

Обратная связь не блокирует выход.

Повторное открытие итогов не создаёт новые записи.

# 12. Состояния и правила переходов

## 12.1. Состояния прогулки

| Состояние | Что означает |
|---|---|
| `active` | Прогулка идёт |
| `paused` | Пользователь поставил её на паузу |
| `completed` | Все шаги обработаны, есть посещения |
| `endedEarly` | Пользователь завершил раньше |
| `cancelledBeforeVisit` | Завершил до первого посещения |

Различать:

- маршрут как подготовленный контент;
- сессию как конкретное прохождение пользователем.

## 12.2. Состояния остановки

Для каждой остановки хранить отдельно **видимость** и **результат**.

**Видимость:**

- скрыта;
- раскрыта.

**Результат:**

- ожидает;
- текущая;
- посещена;
- пропущена;
- заменена.

Так полное раскрытие не превращает будущие места в посещённые.

## 12.3. Состояния миссии

- доступна;
- выполнена;
- пропущена.

Отсутствие взаимодействия не считается выполнением.

## 12.4. Основные правила

1. Ручное подтверждение прибытия создаёт посещение.
2. Посещение создаётся один раз на остановку в рамках сессии.
3. Миссия не влияет на право продолжить.
4. Пропуск не создаёт открытие.
5. Замена не создаёт посещение исходного места.
6. Развилка добавляет только выбранную ветку.
7. Пауза не сбрасывает текущий экран.
8. Закрытие приложения не завершает прогулку.
9. Полное раскрытие сохраняется до конца сессии.
10. Отмена подтверждающего диалога ничего не меняет.

# 13. Моковые данные

## 13.1. Минимальный объём

- 1 город.
- 8 маршрутов.
- По 3–4 основные остановки.
- Не менее 20 разных мест.
- Для каждого маршрута — одна развилка.
- Для ключевых остановок — минимум одна замена.
- 2–3 миссии на маршрут.
- Изображения из локальных assets.
- Все истории и практические сведения доступны без сети.

### Набор маршрутов

| Маршрут | Основная тема | Отличие |
|---|---|---|
| Медленное утро | Еда и спокойствие | Короткий и простой |
| Город руками мастеров | Искусство | Мастерские и детали |
| Вкус района | Гастрономия | Несколько необязательных покупок |
| Тихая сторона города | Отдых | Меньше дистанция |
| Свидание без плана | Для двоих | Совместные миссии |
| Истории за фасадами | Архитектура | Наблюдение |
| Маленькие открытия | Семейный | Короткие переходы |
| После главных достопримечательностей | Смешанный | Более длинная прогулка |

Маршруты должны отличаться условиями, чтобы подбор действительно исключал и ранжировал варианты.

## 13.2. Что должно быть в тестовом контенте

- Полностью бесплатный маршрут.
- Маршрут с обязательным платным входом.
- Маршрут с лестницами.
- Маршрут с подтверждённым отсутствием лестниц.
- Место с неизвестной доступностью.
- Маршрут, недоступный при позднем старте.
- Закрытая остановка с заменой.
- Остановка без доступной замены.
- Бесплатная альтернатива платной миссии.
- Короткое и длинное название.
- Место без фотографии.
- Завершённая прогулка с пропусками.
- Повторное посещение одного места.

Не заполнять интерфейс одинаковыми карточками с разными названиями.

# 15. Расчёты и подбор

## 15.1. Продолжительность

Оценка включает:

- переходы;
- время на остановках;
- выбранную ветку;
- обязательные действия;
- небольшой запас.

Миссии по желанию показываются как возможное дополнительное время.

До выбора ветки маршрут показывает диапазон, учитывающий допустимые варианты.

## 15.2. Дистанция

В моковых данных хранить подготовленные расстояния переходов.

Не рассчитывать пешеходный путь как прямую линию между координатами.

После пропуска или замены использовать подготовленный переход. Если его нет, не показывать выдуманную точность.

## 15.3. Расходы

Разделять:

- обязательные;
- рекомендуемые;
- необязательные.

При замене показывать разницу:

> Примерно на 200–400 больше на человека.

Если точное значение неизвестно, показывать это явно.

## 15.4. Ограничения

**Обязательные условия:**

- доступность;
- максимальная дистанция;
- максимальное время;
- обязательный бюджет;
- подходящее расписание;
- ограничения выбранного семейного формата.

**Предпочтения:**

- настроение;
- интересы;
- виды миссий.

Маршрут, нарушающий обязательное условие, не маркируется как подходящий.

- пропуска;

| Нет открытий | Объяснить, как они появятся |
| Фото отсутствует | Нейтральная тематическая заглушка |
| Фото повреждено | Заглушка, остальные данные доступны |
| Карты не открываются | Адрес и копирование |
| Не удалось сохранить | Сохранить экран, предложить повтор |
| Нет замены | Пропуск, возврат или завершение |
| Клавиатура открыта | Активное поле и действие видимы |
| Приложение закрыто | Восстановить последнюю сохранённую сессию |
| Пользователь отказал в фото | Продолжить без фотографии |
| Список пуст после фильтра | Кнопка сброса фильтров |
| Локальные данные несовместимы | Миграция или безопасное восстановление без молчаливого удаления |

Не показывать сообщение «Проверьте интернет» для ошибки локального сохранения.

# 18. Доступность

- Все интерактивные элементы имеют семантические подписи.
- Выбранность чипов доступна скринридеру.
- Скрытые места действительно скрыты от скринридера.
- Статусы отличаются текстом и формой, а не только цветом.
- Поддерживается системное увеличение шрифта.
- При крупном шрифте сетки переходят в одну колонку.
- Основные кнопки не обрезают текст.
- Контраст обычного текста — не ниже 4,5:1.
- Системное уменьшение движения отключает необязательные эффекты.
- Основной сценарий полностью работает без разрешения на геолокацию.
- Все действия доступны без свайпов и сложных жестов.
- После закрытия модального окна фокус возвращается к вызвавшему элементу.

# 19. Тексты и обратная связь

Тон — дружелюбный, спокойный и конкретный.

### Использовать

- «Можно пропустить».
- «Прогресс сохранён».
- «Эта остановка займёт около 20 минут».
- «Есть бесплатный вариант».
- «Следующее место откроется после этой остановки».

### Не использовать

- «Вы провалили миссию».
- «Вы потеряете награду».
- «Обязательно купите».
- «Идеально безопасный маршрут».
- «Точно открыто», если данные демонстрационные.
- «Вы прошли 5 км», если движение не измерялось.

### Подтверждения действий

Для обычных действий достаточно короткого сообщения:

- «Добавлено в избранное».
- «Заметка сохранена».
- «Миссия выполнена».

Не показывать модальный диалог после каждого успеха.

# 20. Анимации и тактильный отклик

- Выполнение миссии — короткий отклик и отметка.
- Переходы — стандартные платформенные или единообразные.
- Не использовать обязательную анимацию рулетки перед каждой остановкой.
- Не задерживать доступ к навигации ради эффекта.
- Не проигрывать звук автоматически.
- Повторный вход на экран не запускает заново анимацию открытия.

# 23. Критерии приёмки

## 23.1. Первый запуск

- Пользователь проходит онбординг или пропускает его.
- Выбирает город.
- Попадает на обзор.
- При следующем запуске онбординг не повторяется.
- Приложение не запрашивает разрешения заранее.

## 23.2. Подбор

- Все выбранные условия сохраняются при возврате.
- Обязательные ограничения реально влияют на выдачу.
- Причина рекомендации соответствует данным.
- Пустая выдача объясняет, что можно изменить.
- Неизвестная доступность не считается подтверждённой.

## 23.3. Предпросмотр

- До начала видны время, расстояние, расходы и существенные условия.
- Точные места скрыты визуально и семантически.
- Кнопка избранного работает и сохраняется между запусками.

## 23.4. Прохождение

- Одновременно активна только одна сессия.
- Первая точка открывается после старта.
- Следующая — после продолжения или пропуска.
- Прибытие подтверждается без GPS.
- Повторные нажатия не дублируют посещения.
- Возврат из внешних карт сохраняет состояние.
- Миссия не блокирует продолжение.
- Замена меняет точку и расчётные параметры.
- Пропуск не добавляет место в атлас.
- Развилка сохраняет только выбранный путь.
- Полное раскрытие не помечает места посещёнными.
- Пауза сохраняется после перезапуска.

## 23.5. Завершение

- Полное и досрочное завершение имеют корректные тексты.
- Показатели не выдают расчётные значения за измеренные.
- Итоги учитывают пропуски и замены.
- Обратную связь можно пропустить.
- Повторный просмотр итогов не дублирует данные.

## 23.6. Атлас

- Посещённое место появляется без обязательной миссии.
- Повторное посещение связано с существующим местом.
- Заметки и фотографии сохраняются после перезапуска.
- Фото не теряется после очистки временных файлов picker.
- Пустое состояние ведёт к началу прогулки.

## 23.7. Устойчивость

- Основной сценарий работает без интернета.
- Все изображения основного контента доступны локально.
- Ошибка карт не блокирует прогулку.
- Ошибка сохранения не изображается как успешное действие.
- Нет переполнений на компактном экране и при увеличенном шрифте.
- Быстрые повторные нажатия не ломают навигацию.

# 24. Что проверить тестами

Автоматически проверить логику, от которой зависит целостность опыта:

- фильтрацию по обязательным ограничениям;
- расчёт времени и расходов для веток;
- переходы состояний прогулки;
- отсутствие дубликатов посещений;
- замену и пропуск;
- восстановление сессии;
- повторное посещение места;
- сохранение выбранной ветки;
- отсутствие скрытых названий в предпросмотре.

Интеграционный сценарий:

> Первый запуск → подбор → начало → посещение → миссия → замена → развилка → завершение → атлас → перезапуск.

Отдельный сценарий:

> Начало → пауза → закрытие приложения → восстановление → досрочное завершение.

Визуально проверить основные экраны на компактном устройстве, крупном устройстве и с увеличенным системным шрифтом.
